管理面板为管理员提供了对 Warp 中团队设置的集中控制。从单一界面配置代理行为、安全策略、代码库索引和协作功能。

## 什么是管理面板？

[管理面板](https://app.warp.dev/admin/)是你大规模管理 Warp 的控制中心。它允许 IT 管理员、平台团队和工程经理：

* **控制代理行为** - 在组织范围内设置自主级别、命令权限和安全护栏
* **执行安全策略** - 配置密钥编辑、遥测控制和数据处理
* **管理团队资源** - 启用代码库上下文、配置 BYOLLM 和控制共享权限
* **监控使用情况** - 跟踪积分消耗并设置支出限制
* **保持合规** - 应用满足组织安全要求的一致策略

:::note
Warp 限制管理面板仅对团队管理员开放。普通团队成员可以查看影响他们的设置，但不能修改组织范围的策略。
:::

## 访问管理面板

### 团队管理员

通过两种方式访问管理面板：

**方式 1：直接 URL**
1. 导航到 [app.warp.dev/admin](https://app.warp.dev/admin/)。
2. 使用你的 SSO 凭据登录。
3. 管理面板将打开，显示所有组织设置。

**方式 2：从 Warp 设置**
1. 打开 Warp，点击右上角的个人资料图标。
2. 点击 **设置**。
3. 导航到 **管理面板** 标签页（仅对团队管理员可见）。

### 团队成员

团队成员可以在其个人设置面板中看到组织强制执行的设置：

* 由管理员控制的设置显示为灰色
* 由消息提示："你的组织已配置此设置"
* 在管理员选择"尊重用户设置"的地方，用户可以保留控制权

## 设置强制执行机制

管理面板使用三层强制执行模型，让管理员保持控制的同时允许适当的灵活性。

### 设置强制执行级别

**组织强制执行**
* 设置适用于所有团队成员，无论个人偏好如何
* 用户无法覆盖这些设置
* 用于安全关键策略（例如密钥编辑、命令阻止列表）

**尊重用户设置**
* 允许团队成员自行控制该设置
* 管理员设置默认值，但用户可以自定义
* 用于不影响安全或合规的偏好（例如 AI 模型选择）

**层级限制**
* 设置基于计费计划锁定
* 在计划升级之前无法更改
* 由消息提示："配置此设置在你的计划上不可用"

### 强制执行前测试

:::note
在管理面板中进行的更改会立即对所有团队成员生效。在应用组织范围的强制执行之前，请在你的 Warp 环境中测试设置。
:::

要安全地推出新策略：

1. 初始时将设置配置为"尊重用户设置"。
2. 在小范围用户中测试。
3. 收集反馈并调整配置。
4. 验证后切换为"组织强制执行"。

## 计划限制

管理面板中可用的功能随你的 Warp 计划而扩展：

### 免费版
* 大多数设置是固定的，不可配置
* 有限的代码库上下文（2 个仓库）
* 不支持 BYOLLM
* 基础共享功能

### 商业版计划
* 大多数设置可由管理员配置
* 增强的代理自主性控制
* 高级共享和隐私功能
* 增加的代码库上下文限制

### 企业版计划
* **完全管理员控制** - 配置所有可用设置
* **企业密钥编辑** - 用于密钥的自定义正则表达式模式
* **BYOLLM** - 通过你的云基础设施路由推理
* **自托管云代理工作进程** - 在你自己的基础设施上部署云代理工作进程
* **高级合规** - SOC 2、HIPAA 和自定义数据处理协议
* **优先支持** - 专属的 Slack/Teams 频道

有关完整的计划详情，请访问 [warp.dev/pricing](https://www.warp.dev/pricing) 或[联系销售](https://www.warp.dev/contact-sales)。

## 管理面板区域

管理面板分为六个主要区域：

### AI 设置

配置代理在组织中的行为方式，包括自主级别和命令权限。这是你在代理生产力与组织安全要求之间取得平衡的地方。

#### 通用 AI 设置

**远程会话中的 AI**
* 控制代理在 SSH 会话和远程连接期间是否可用
* 企业版计划可以切换此设置
* 考虑对生产服务器或敏感环境禁用

**提示摘要缓存**
* 当对话变长时，LLM 提供商临时缓存摘要
* 改善长时间代理交互的性能
* 零数据保留协议涵盖缓存（短期）

#### 自主性设置

配置代理在执行操作时拥有多大的独立性。可选择：

* **代理决定** - 代理在自信时自主行动，不确定时询问（推荐）
* **始终询问** - 每个操作都需要明确批准
* **始终允许** - 最大自主性，无需确认
* **尊重用户设置** - 允许个人用户设置其偏好

**应用代码差异**
控制代理是否可以在未经批准的情况下应用代码更改。对于生产关键代码库，考虑使用"始终询问"以保持严格控制。

**创建计划**
代理是否可以在没有用户批准的情况下创建结构化任务计划（`/plan` 命令）。

**执行命令**
管理代理自主运行终端命令的能力。与命令允许列表/阻止列表配合使用以实现细粒度控制。

**读取文件**
控制代理读取代码库中文件的访问权限。启用可获得更好的上下文，对敏感仓库进行限制。

#### 目录和命令控制

**目录允许列表**
指定代理可以不受限制地读取文件的目录。使用绝对路径：
* `~/git/internal-tooling` - 授予对特定项目的访问权限
* `/home/user/repos/public-*` - 使用通配符匹配模式

**命令允许列表**
匹配代理可以无需询问即可执行的命令的正则表达式。常见模式：
* `grep .*` - 文本搜索
* `ls(\\s.*)?` - 目录列表
* `git status` - 版本控制查询
* `which .*` - 查找可执行文件

**命令阻止列表**
无论自主性设置如何，**始终**需要明确用户批准的命令的正则表达式：
* `rm -rf.*` - 递归删除
* `sudo.*` - 管理命令
* `curl.*|wget.*` - 网络请求
* `docker rm.*` - 容器操作
* `.*production.*` - 包含"production"的命令

:::caution
命令阻止列表规则优先于允许列表规则和代理自主性设置。使用阻止列表可以防止高风险操作，即使在高度自主的配置中也是如此。
:::

### 隐私设置

管理数据收集和安全策略，以满足组织的合规要求。

**用户生成内容（UGC）数据收集**
控制 Warp 如何收集和使用用户生成内容以改进服务：
* **禁用** - Warp 不从你的组织收集任何 UGC 数据
* **启用** - 允许数据收集以改进服务
* **尊重用户设置** - 让个人用户自行决定

拥有零数据保留协议的企业团队可以完全禁用它。

**企业密钥编辑**
在发送数据到 LLM 提供商之前自动检测并编辑敏感信息：
* 企业版计划默认启用此功能
* 包括常见密钥模式的自动检测（API 密钥、密码、证书）
* 支持用于组织特定密钥的自定义正则表达式模式
* 无条件适用于所有团队成员

在管理面板中配置自定义模式以匹配你组织的密钥格式。

### 代码设置

控制团队的代码库索引和代理代码功能。

**代码库上下文**
决定 Warp 是否索引团队的 Git 仓库以为代理提供上下文：
* **禁用** - 不进行代码库索引
* **启用** - 索引代码库以在大型多仓库系统中改善代理响应
* **尊重用户设置** - 允许个人控制

启用后，代理能够理解所有已索引仓库中的代码模式、架构和约定。企业版计划支持：
* 无限制的仓库数量
* 每个仓库最多 200,000 个文件
* 具有集中配置的团队范围索引

### 账单设置

配置账单偏好和支出控制，以大规模管理成本。

**按使用量计费**
启用超出计划包含配额的积分的按需付费计费：
* 设置每月支出限制以控制成本
* 查看当前超额使用量和成本
* 在接近支出阈值时接收告警

**积分分配**
对于具有协商积分池的企业版计划：
* 跨团队或项目分配积分
* 按团队监控使用情况
* 设置每团队支出限制

请联系你的客户经理配置高级积分分配。

### 共享设置

控制团队成员如何进行协作和共享 Warp Drive 资源。

**直接链接共享**
允许团队成员通过直接链接共享笔记本、工作流、提示和其他 Warp Drive 对象：
* **启用** - 团队成员可以生成可共享的链接
* **仅团队** - 链接仅对团队成员有效
* **禁用** - 不允许链接共享

**拥有链接的任何人共享**
启用对共享对象的公共访问：
* **启用** - 任何拥有链接的人都可以查看内容，无需成为团队成员
* **禁用** - 链接需要团队成员身份才能访问

对于具有敏感内部流程的组织，请禁用"拥有链接的任何人"共享以防止意外泄露。

### 平台设置

配置团队的云代理设置，包括用于自动化工作流的 GitHub 授权。

**启用的 GitHub 组织**

**启用的 GitHub 组织**设置将你的 Warp 团队与一个或多个 GitHub 应用安装相关联，使通过[团队 API 密钥](/reference/cli/api-keys/)启动的云代理能够使用 Oz by Warp GitHub 应用克隆仓库和创建拉取请求。

配置方法：

1. 导航到管理面板的**平台**部分。
2. 在**启用的 GitHub 组织**下，查看已安装 Oz by Warp GitHub 应用的 GitHub 组织列表。
3. 选择你的团队应有权访问的组织。

## 多管理员功能

Warp 支持多个团队管理员，以防止单点故障并实现分布式管理。

### 提升和降级管理员

团队管理员可以授予或撤销管理员权限：

1. 导航到**设置** > **团队** > **团队成员**。
2. 找到你要修改的用户。
3. 点击其姓名旁边的角色下拉菜单。
4. 选择 **Admin** 或 **Member**。
5. 点击 **Save**。

:::note
我们建议除了团队所有者外至少还有一个管理员，以防某人无法访问时出现问题。团队所有者具有完全访问权限并可转让所有权；团队管理员具有相同的权限，但不能转让所有权。
:::

## 常见管理工作流

### 初始企业设置

购买 Warp 企业版计划后：

1. **配置 SSO** - 使用你的身份提供商设置认证。
2. **启用代码库上下文** - 索引组织的仓库。
3. **设置代理自主性** - 配置初始安全级别。
4. **应用密钥编辑** - 为你的组织添加自定义模式。
5. **配置 BYOLLM**（可选）- 通过你的云账户路由推理。
6. **创建共享资源** - 用工作流、规则和提示填充团队 Warp Drive。

关于用户角色和访问控制的详细信息，请参见[角色与权限](/enterprise/team-management/roles-and-permissions/)。

### 为不同团队调整策略

对于拥有多个团队的组织（例如 DevOps、数据、前端）：

1. 为每个组创建单独的 Warp 团队。
2. 分配团队特定的管理员。
3. 为每个团队配置不同的自主级别。
4. 使用目录允许列表将代理访问范围限定到团队仓库。

### 响应安全事件

如果代理执行了意外操作：

1. **立即：** 在受影响用户的会话中查看代理操作日志。
2. **短期：** 将特定命令添加到命令阻止列表。
3. **长期：** 调整自主性设置以防止类似事件。
4. **审查：** 检查受影响用户团队的管理面板设置，确认当时生效的自主级别、允许列表和限制。

Warp 记录所有代理操作并附带完整上下文，使事件调查变得简单。

## 故障排除

### 用户看不到新设置

**问题：** 你在管理面板中更改了设置，但用户报告说他们看不到更改。

**解决方案：**
1. 确认该设置未设为"尊重用户设置"。
2. 要求用户重启 Warp 以强制刷新设置。
3. 确认用户是正确团队的成员。
4. 检查用户是否已通过 SSO 登录（而非个人账户）。

### 管理面板中的设置显示为灰色

**问题：** 你想配置的设置显示为灰色或显示"在你的计划上不可用"。

**解决方案：**
* 此设置仅限于更高层级的计划
* 在 [warp.dev/pricing](https://www.warp.dev/pricing) 上查看计划功能
* 联系你的客户经理或[销售团队](https://www.warp.dev/contact-sales)进行升级

### 命令允许列表不起作用

**问题：** 代理仍然对与允许列表模式匹配的命令询问许可。

**解决方案：**
1. 验证正则表达式模式是否正确（使用正则表达式验证器测试）。
2. 检查命令是否也匹配阻止列表（阻止列表优先）。
3. 确认自主性设置允许命令执行。
4. 请记住：某些命令无论允许列表如何都始终受限。
