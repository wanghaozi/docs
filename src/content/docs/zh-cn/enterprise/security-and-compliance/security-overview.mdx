Warp 将安全与合规构建到其核心中，**让开发者保持控制**，同时赋能强大的代理工作流。本概述解释了 Warp 如何处理你的数据、有哪些安全控制可用，以及 Warp 如何满足企业安全标准。

## 透明度与控制

Warp 的安全理念以**透明度和开发者控制**为核心：

* **完全可见性** - 通过我们的[详尽遥测表](/support-and-community/privacy-and-security/privacy/#exhaustive-telemetry-table)精确查看收集了哪些遥测数据
* **实时监控** - 使用 Warp 的[网络日志](/support-and-community/privacy-and-security/network-log/)实时监控所有网络请求
* **退出控制** - 随时禁用遥测和崩溃报告，同时保留全部功能
* **团队级执行** - 管理员可为整个组织配置遥测和数据收集策略
* **开源客户端** - Warp 的客户端代码以 [AGPL v3](https://github.com/warpdotdev/warp/blob/master/LICENSE-AGPL) 协议发布在 [`warpdotdev/warp`](https://github.com/warpdotdev/warp) 上，安全团队可以直接审计代码库。关于源代码仓库和安全报告流程，请参见[向 Warp 贡献](/support-and-community/community/contributing/)。

## Warp 收集哪些遥测数据以及为什么？

### 零数据保留（ZDR）

Warp 与其签约的 LLM 提供商（Anthropic、OpenAI、Google）签订了**零数据保留（ZDR）**协议，这意味着它们不会存储或基于你的数据进行训练。ZDR 适用于所有 Warp 计划。

按计划划分的数据收集方式：

* **免费版** - 个人用户可以在**设置** > **隐私**中禁用数据收集。
* **付费团队** - 团队管理员可以为整个团队强制执行数据收集设置。数据收集默认启用。
* **商业版和企业版** - 团队管理员可以为整个团队强制执行数据收集设置。数据收集**默认禁用**。

:::note
某些产品功能——包括云对话和 Oz 运行——需要存储对话数据才能运行。这些数据用于支撑产品体验，与分析或遥测数据收集分开。
:::

企业版订阅还包括：

* **团队级执行** - 管理员通过管理面板为整个组织配置数据收集和遥测策略
* **密钥编辑** - 所有 AI 交互自动应用[密钥编辑](/support-and-community/privacy-and-security/secret-redaction/)以防止敏感数据泄露

### 遥测类别

启用遥测后，Warp 会收集：

1. **产品使用分析** - 关于功能采用和使用模式的高层指标（例如"代理模式已打开"、"工作流已执行"）。
2. **性能和稳定性** - 崩溃报告、错误跟踪和性能指标，用于识别和修复问题。

禁用数据收集后，Warp 不会收集：

* 超出用户 ID 和邮箱地址的个人身份信息
* 网络流量或外部 API 调用

### 禁用遥测

用户可以单独选择退出遥测：

1. 导航到**设置** > **隐私**。
2. 关闭**帮助改进 Warp** 和/或**发送崩溃报告**。

遥测禁用后，Warp 停止收集用于分析目的的使用情况和交互数据。

团队管理员可以通过管理面板在组织范围内强制执行遥测设置。在商业版和企业版计划中，数据收集默认禁用。

## 数据处理与隐私

### 你的数据存储在哪里

* **代码和文件** - 保留在你的本机上，除非你明确使用需要传输它们的功能（例如代码库上下文索引、会话共享、Warp Drive 团队资源）
* **代码库上下文** - 索引过程中，代码被发送到 Warp 的服务器以生成嵌入向量；原始代码不会被存储，只保留生成的嵌入向量
* **代理请求** - Warp 向签约的 LLM 提供商（Anthropic、OpenAI、Google）发送请求，企业团队享有零数据保留协议
* **BYOLLM** - 请求通过 Warp 的服务器代理到你的云基础设施，推理在此运行。Warp 不存储这些请求的内容。
* **自托管云代理执行** - 仓库克隆、构建产物、运行时密钥和执行工作区保留在你的基础设施上。编排元数据、会话记录以及 LLM 推理请求和响应通过 Warp 路由（受 ZDR 约束），可能包含代理交互中的代码上下文。

### 加密

* **传输中** - 传输到 Warp 服务器的所有数据都使用 TLS 1.2 或更高版本
* **静态存储** - Warp 使用 AES-256 加密所有静态用户数据

### 密钥编辑

Warp 在向 LLM 提供商发送任何数据之前自动检测并编辑敏感信息，让开发者控制哪些内容被共享：

* API 密钥和令牌
* 密码和密钥
* SSH 密钥和证书
* 自定义密钥模式（可通过管理面板配置）

详情请参见[密钥编辑文档](/support-and-community/privacy-and-security/secret-redaction/)。

### 数据保留

* **ZDR** - Warp 签约的 LLM 提供商不保留或基于你的数据进行训练
* **遥测数据** - 收集时，Warp 会无限期保留遥测数据用于分析和调试
* **用户账户** - 数据删除请求在经过验证的认证并遵守法律和合同义务后，在 30 天内安全处理，无需额外费用

## 合规与认证

### SOC 2 Type II

Warp 已获得 SOC 2 Type II 认证，在以下方面符合行业标准的安全控制要求：

* **安全** - 基础设施保护、访问控制和监控
* **可用性** - 系统正常运行时间和灾难恢复
* **保密性** - 数据保护和隐私控制
* **处理完整性** - 准确、完整且经过授权的处理

SOC 2 报告可根据要求提供给企业客户。

## 基础设施安全

### Warp 托管基础设施

使用 Warp 托管的基础设施时：

* **云提供商** - 托管在通过 SOC 2 和 ISO 27001 认证的 GCP 数据中心
* **网络隔离** - 工作负载在具有严格网络策略的隔离 VPC 中运行

Warp 的运营安全实践——包括访问控制、监控和漏洞管理——已通过 SOC 2 Type II 认证验证。详情请参见[合规与认证](#compliance-and-certifications)。

### 自托管部署

企业团队可以自托管云代理执行，以控制代理的运行位置并将仓库保留在自己的基础设施上。

自托管部署采用分离架构：
* **执行平面（客户托管）** - 仓库克隆、构建产物、运行时密钥和容器文件系统状态保留在你的基础设施上
* **控制平面（Warp 托管）** - 会话记录（包含来自代理交互的代码上下文）、编排元数据和 LLM 推理通过 Warp 的服务器路由（受零数据保留协议约束）。Warp 不会持久存储你的源代码或将其用于模型训练

提供两种部署模式：
* **非托管模式** - 使用 `oz agent run` 在你的现有编排器或 CI 环境中运行代理。支持 Linux、macOS 和 Windows，无需 Docker 依赖。
* **托管模式** - 运行 `oz-agent-worker` 守护进程，让 Oz 平台在你的基础设施上的隔离 Docker 容器中编排代理。

两种模式下，代理运行都完全可跟踪和可控制。无需入站网络访问。

**网络出站要求**

自托管代理需要出站访问 Warp 的后端服务，对于托管架构，还需要访问 Docker Hub 和 GitHub。

## 访问控制与认证

### 单点登录（SSO）

Warp 支持通过 Okta、Microsoft Entra ID、Google Workspace、OneLogin 以及任何兼容 SAML 2.0 或 OpenID Connect（OIDC）的提供商进行 SSO。管理员可以要求所有团队成员使用 SSO，并通过你的身份提供商强制执行 MFA。

设置说明、SCIM 配置、账户链接和故障排除，请参见[单点登录（SSO）](/enterprise/security-and-compliance/sso/)。

### 团队权限

Warp 使用基于角色的访问控制，包含三种角色——团队所有者、团队管理员和成员——用于管理团队访问和管理面板权限。详情请参见[用户角色与权限](/enterprise/getting-started/getting-started-enterprise/#user-roles-and-permissions)。

Warp Drive 中的资源共享对谁可以查看、编辑和共享具有细粒度控制。

### 管理面板治理

管理面板为安全和 IT 团队提供了对 AI 行为、数据处理和共享策略的集中控制。设置可以**强制执行**（覆盖整个组织中个人用户的偏好）或设置为**尊重用户设置**（遵循个人偏好）。

与安全相关的控制包括：
* **隐私** - 配置用户生成内容（UGC）数据收集、云对话存储和企业密钥编辑
* **共享** - 限制或允许直接链接共享和"拥有链接的任何人"共享权限
* **AI** - 配置团队的 AI 自主性设置和通用代理行为
* **模型** - 控制哪些 LLM 模型对团队成员可用，包括 AWS Bedrock
* **平台** - 配置云代理访问和设置

## 面向开发者的安全功能

### 自带 LLM（BYOLLM）

通过你自己的云基础设施路由代理推理，实现完全控制：

* **数据驻留** - 交互式代理推理在你的 AWS 账户中运行
* **云原生 IAM** - 使用用户现有的身份和访问管理流程进行认证
* **不存储密钥** - Warp 从不会存储你的云凭证或 API 密钥
* **账单控制** - 推理成本直接计入你的云账户

配置详情请参见[自带 LLM](/enterprise/enterprise-features/bring-your-own-llm/)。

### Docker 沙箱

在容器化环境中隔离代理执行：

* **进程隔离** - 代理在独立的 Docker 容器中运行，与你的主机系统隔离
* **资源限制** - 为每个沙箱配置 CPU、内存和磁盘配额
* **网络控制** - 限制沙箱的出站网络访问
* **临时环境** - 沙箱使用后即销毁，不留痕迹

### 代理权限

配置代理可以访问和执行的内容：

* **工具限制** - 启用/禁用终端使用、代码编辑、网络搜索和文件系统访问
* **仓库范围限定** - 将代理限制到特定的仓库或目录
* **执行审批** - 敏感命令需要手动批准
* **可见性** - 启用云对话存储后，代理操作会记录完整上下文供审查

## 事件响应与支持

### 安全问题报告

如果你在 Warp 中发现安全漏洞：

1. 发送邮件至 [security@warp.dev](mailto:security@warp.dev)。
2. 包含详细的复现步骤。
3. 在 Warp 解决该问题之前，请勿公开披露。

Warp 遵循负责任的披露实践，并与报告者协调披露时间表。

### 企业支持

企业客户获得优先安全支持：

* **专属渠道** - 用于安全问题的私有 Slack/Teams 频道
* **安全公告** - 主动通知安全更新
* **事件协助** - 安全事件或数据泄露调查期间的支持
* **合规协助** - 帮助处理合规问卷和审计
