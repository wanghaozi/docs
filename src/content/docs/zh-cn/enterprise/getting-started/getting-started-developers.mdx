本指南帮助开发者快速在 Warp 中与团队一起开展工作。你将了解如何下载 Warp、使用组织的 SSO 登录，以及配置代码库上下文（Codebase Context）、Warp Drive 和代理配置文件（Agent Profiles）等关键功能，从而在整个 SDLC 中加速你的工作（全程保持在你熟悉的终端中）。

在 Warp 中使用代理时，你实际上是在使用 **Warp 的内置代理**。Oz 是 Warp 的可编程代理，用于大规模运行和协调代理——无论是在本机运行还是在云端运行。Oz 提供了编排、跟踪和控制平面，使代理工作流能够无缝扩展。

:::note
刚接触 Warp 企业版？试试[企业版快速入门](/enterprise/getting-started/quickstart/)，10 分钟完成 SSO 登录、Warp 设置和运行你的第一个代理。
:::

## 第 1 步：下载并安装 Warp

Warp 适用于 macOS、Linux 和 Windows。

### 下载 Warp

访问 [warp.dev/download](https://www.warp.dev/download) 选择你的平台：

* **macOS** - 下载 `.dmg` 安装程序（需要 macOS 10.15 Catalina 或更高版本）
* **Linux** - 下载 `.deb`、`.rpm` 或使用安装脚本
* **Windows** - 下载 `.exe` 安装程序（需要 Windows 10 或更高版本）

### 安装 Warp

**macOS：**
1. 打开下载的 `.dmg` 文件。
2. 将 Warp 拖到 Applications 文件夹。
3. 从 Applications 或 Spotlight 启动 Warp。

**Linux：**
```bash
# Debian/Ubuntu
sudo dpkg -i warp-terminal_*.deb

# Fedora/RHEL
sudo rpm -i warp-terminal-*.rpm

# 或者使用安装脚本
curl -fsSL https://www.warp.dev/install.sh | bash
```

**Windows：**
1. 运行下载的 `.exe` 安装程序。
2. 跟随安装向导。
3. 从开始菜单启动 Warp。

## 第 2 步：登录你的团队

### 通过 SSO 登录

如果你的组织使用 SSO（大多数企业团队都这样）：

1. 启动 Warp。
2. 按提示登录或创建账户。
3. 点击 **Continue with SSO**。
4. 输入你的工作邮箱或组织域名。
5. 重定向到你的身份提供商后，使用你的 SSO 凭据完成认证。

:::caution
不要试图直接从你的 SSO 提供商应用门户（例如 Okta 仪表板）启动 Warp。这将导致错误。始终通过 [app.warp.dev/login](https://app.warp.dev/login) 登录 Warp。
:::

### 通过邀请链接登录

如果你从团队管理员那里收到了邀请链接：

1. 点击邮件或消息中的邀请链接。
2. 在注册页面，如果你的团队已配置 SSO，请使用 SSO 登录；否则使用其他登录方式（Google、GitHub 或邮箱）。
3. 认证后，你将自动加入团队。

### 将现有账户链接到 SSO

如果你的组织在启用 SSO 之前你已经在使用 Warp：

1. 访问 [app.warp.dev/login](https://app.warp.dev/login)。
2. 使用你的原始方式（邮箱、Google 或 GitHub）登录。
3. 登录后，导航到 [app.warp.dev/link_sso](https://app.warp.dev/link_sso)。
4. 按照提示将你的账户链接到 SSO。
5. 以后请使用 **Continue with SSO** 登录。

## 第 3 步：设置关键功能

### 代码库上下文

代码库上下文（Codebase Context）会索引你的 Git 仓库，使代理能够理解你的代码，并在大型多仓库系统中提供准确且上下文感知的回答。

**设置代码库上下文：**

首先，在设置中启用代码库索引：

1. 进入**设置** > **代码** > **索引和项目**。
2. 将**启用代码库索引**开关打开。
3. （可选）启用**默认索引新文件夹**，这样当你导航到新仓库时会自动索引。

:::caution
代码库上下文是团队管理员控制的功能。如果你看不到这些设置或它们被禁用，请联系你的管理员为团队启用此功能。
:::

**索引你的仓库：**

启用代码库索引后，你可以索引单个仓库：

1. 在终端中导航到一个 Git 仓库。
2. 运行 `/init` 命令。
3. Warp 开始索引你的代码库。
4. 系统会提示你创建一个 `AGENTS.md` 文件（可选，但推荐）。

**被索引的内容：**

* 仓库中所有由 Git 跟踪的文件
* 每个仓库最多 200,000 个文件
* `.gitignore` 或 `.warpindexingignore` 中排除的文件会自动跳过

**隐私说明：**

在索引过程中，你的代码会被发送到 Warp 的服务器进行处理，生成嵌入向量并存储。代码本身不会被保存——只有嵌入向量会持久化。这使得代理能够理解你的代码库结构和上下文，而无需存储你的实际源代码。

:::note
对于云代理：当代理创建或修改文件时，代码片段可能会作为对话记录的一部分被存储，因为差异（diffs）会保留在对话历史中。
:::

### 代理配置文件

{/* Warp also supports third-party CLI agents (Claude Code, Codex, Copilot), so we say "built-in" rather than "every." */}
代理配置文件（Agent Profiles）让你配置 Warp 内置代理的行为方式。配置文件让你直接控制代理工作流的模型选择、自主性、工具和权限。

**创建代理配置文件：**

1. 进入**设置** > **代理** > **配置文件**。
2. 点击 **New Profile**。
3. 配置：
   * **名称和描述**
   * **模型** - 选择使用哪个 LLM
   * **自主级别** - 代理在多大程度上可以自主行动而不征求你的意见
   * **工具** - 启用/禁用终端使用、代码编辑、网络搜索
   * **权限** - 代理可以访问的内容（仓库、文件、密钥）
4. 点击 **Save**。

**使用配置文件：**

根据任务切换不同的配置文件：
* **高自主性** 用于日常任务，如编写测试或更新文档
* **低自主性** 用于敏感操作，如基础设施变更
* **特定模型** 用于成本优化或特定任务需求

### Warp Drive

Warp Drive 是你的工作空间，用于保存和共享工作流（Workflows）、笔记本（Notebooks）、提示（Prompts）、规则（Rules）和环境变量（Environment Variables）。

**访问 Warp Drive：**

1. 点击 Warp 左上角的工具面板图标。
2. 点击工具面板顶部的 Warp Drive 图标。
3. 显示两个 Warp Drive 区域：
   * **团队**（上方）- 团队共享的资源。
   * **个人**（下方）- 你个人的资源。

**你可以添加到 Warp Drive 的内容：**

* **工作流** - 你反复使用的参数化命令（例如部署脚本、环境设置）
* **笔记本** - 结合 Markdown 和可执行代码块的交互式运行手册
* **提示** - 为重复性任务保存的代理提示（例如"审查这个 PR"、"编写单元测试"）
* **计划** - 代理生成的复杂任务执行计划，代理可以逐步执行
* **规则** - 代理应遵循的编码标准和约定
* **环境变量** - 可加载到终端会话中的配置

**创建你的第一个工作流：**

1. 在 Warp Drive 中，点击个人或团队部分的 **+**。
2. 选择 **Workflow**。
3. 输入名称、描述和命令。
4. 如果需要，添加参数（例如 `{{branch_name}}`）。
5. 点击 **Save**。

**使用团队资源：**

你的团队管理员可能已经创建了共享资源。浏览 Warp Drive 的团队部分，看看有什么可用的——包括入职笔记本、部署工作流和编码标准规则。

### MCP（模型上下文协议）

MCP 将 Warp 的代理连接到外部工具和服务，以增强上下文。

**配置 MCP 服务器：**

1. 进入**设置** > **代理** > **MCP 服务器**，或通过 Warp Drive 访问。
2. 浏览可用的 MCP 服务器库：
   * **Linear** - 访问问题和项目上下文
   * **Sentry** - 获取错误跟踪和堆栈跟踪信息
   * **Figma** - 参考设计和规格说明
   * **GitHub** - 访问仓库和 PR 上下文
   * 以及更多...
3. 点击服务器旁边的 **+** 添加它。
4. 配置凭据和连接详情。
5. 根据需要开关服务器。

你的团队可能已共享了 MCP 配置。检查团队配置的服务器旁边的共享图标，无需手动设置即可使用。

## 第 4 步：开始使用 Warp

### 日常工作流

Warp 让你在终端中完成整个 SDLC，并随时获得代理的帮助：

**环境设置**
* "设置 Node 20、Python 3.12 和 Docker Desktop"
* 将设置步骤保存为 Warp Drive 中的工作流，供以后使用

**理解代码库**
* "认证在这个系统中是如何流转的？"
* "这个仓库在错误处理上使用了什么模式？"

**编写代码**
* 对复杂功能使用 `/plan` 命令
* 通过代码审查面板实时查看差异（diff）
* 在特定行上留下评论让代理处理

**调试**
* 启动调试器（`gdb`、`lldb`）并引入代理
* 代理可以用自然语言操作调试器和 REPL
* 将终端输出附加到代理对话中进行分析

**版本控制**
* "暂存这些更改并撰写详细的提交信息"
* "按照我们的模板创建带有描述的 PR"
* 设置规则以强制执行 Git 提交约定

**测试**
* "按照我们现有的模式为这个函数编写单元测试"
* "运行测试套件并解释哪些失败了"
* 配置云代理在后台运行测试套件并验证 PR 的覆盖率
