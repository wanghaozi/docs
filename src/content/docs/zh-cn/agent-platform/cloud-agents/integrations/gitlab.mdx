云 Agent 适用于任何 Git 仓库，包括托管在 GitLab 上的仓库。与 GitHub 不同，GitLab 没有原生的 Warp 集成，但您可以使用个人访问令牌和 Warp 管理的密钥授予 agent 访问您的 GitLab 仓库的权限。配置后，您的环境适用于任何 Oz 触发器——Slack、Linear、计划或 CLI。

此页面说明如何生成 GitLab 个人访问令牌、安全存储它，以及配置在运行时克隆您的仓库的云 agent 环境。

:::note
此方法同时适用于 GitLab.com 和自托管的 GitLab 实例。
:::

---

## 前提条件

* Warp 账户（[在 oz.warp.dev 创建账户](https://oz.warp.dev)）
* 托管在 GitLab（云或自托管）上的仓库
* 已安装并认证的 [Oz CLI](/reference/cli/)

---

## 第 1 步：生成个人访问令牌

1. 登录 GitLab。
2. 点击右上角的头像，然后点击**编辑配置文件**。
3. 在左侧边栏中，点击**访问**，然后点击**个人访问令牌**。
4. 点击**添加新令牌**。
5. 输入描述性名称（例如 `warp-oz-agent`），并选择与团队轮换策略匹配的到期日期。
6. 在**选择范围**下，选择 **read_repository**。
7. 点击**生成令牌**。
8. 立即复制令牌值。GitLab 不会再次显示它。

:::note
**read_repository** 是克隆仓库所需的最小范围。如果未来的工作流要求 agent 推送提交或打开合并请求，您还需要 **write_repository**。
:::

---

## 第 2 步：将令牌存储为 Warp 管理的密钥

```bash
oz secret create --team GITLAB_TOKEN
```

提示时粘贴令牌。

:::note
使用 `--team` 创建共享令牌，使用 `--personal` 使每个团队成员使用自己的令牌。
:::

---

## 第 3 步：使用克隆设置命令创建环境

```bash
oz environment create \
  --name "my-gitlab-env" \
  --docker-image <image> \
  --setup-command 'git clone https://oauth2:$GITLAB_TOKEN@gitlab.com/your-group/your-repo.git' \
  --setup-command 'cd your-repo && <install dependencies>'
```

:::caution
使用单引号，以便 `$GITLAB_TOKEN` 在运行时在容器内部展开。
:::

---

## 第 4 步：测试您的环境

```bash
oz agent run-cloud --environment <ENV_ID> --prompt "Your task here"
```

---

## 后续步骤

* **Slack** — 标记 **@Oz** 以启动针对 GitLab 仓库的 agent 运行。
* **Linear** — 标记 **@Oz** 以启动工作流。
* **计划 Agent** — 按重复计划运行 agent。
