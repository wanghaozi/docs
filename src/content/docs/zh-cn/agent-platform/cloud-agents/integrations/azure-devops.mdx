云 Agent 适用于任何 Git 仓库，包括托管在 Azure DevOps 上的仓库。原生 Azure DevOps 集成尚不可用，但您可以使用个人访问令牌和 Warp 管理的密钥授予 agent 访问您的仓库的权限。配置后，您的环境适用于任何 Oz 触发器——Slack、Linear、计划或 CLI。

此页面说明如何生成 Azure DevOps 个人访问令牌、安全存储它，以及配置在运行时克隆您的仓库的云 agent 环境。

:::note
此方法同时适用于 Azure DevOps Services（dev.azure.com）和 Azure DevOps Server（自托管）实例。
:::

---

## 前提条件

* Warp 账户（[在 oz.warp.dev 创建账户](https://oz.warp.dev)）
* 托管在 Azure DevOps（云或自托管）上的仓库
* 已安装并认证的 [Oz CLI](/reference/cli/)

---

## 第 1 步：生成个人访问令牌

1. 在 `dev.azure.com/{your-org}` 登录您的 Azure DevOps 组织。
2. 点击右上角的用户设置图标（齿轮），然后点击**个人访问令牌**。
3. 点击 **+ 新建令牌**。
4. 输入描述性名称（例如 `warp-oz-agent`），选择适用的组织，设置与团队轮换策略匹配的到期日期。
5. 在**范围**下，选择**自定义定义**，然后选择**代码** > **读取**。
6. 点击**创建**。
7. 立即复制令牌值。Azure DevOps 不会再次显示它。

:::note
**代码（读取）** 是克隆仓库所需的最小范围。如果未来的工作流要求 agent 推送提交或打开拉取请求，您还需要**代码（读取和写入）**。
:::

:::note
对于 Azure DevOps Server（自托管），在 `https://{server}/{collection}` 登录，而非 `dev.azure.com`。令牌创建步骤相同。
:::

---

## 第 2 步：将令牌存储为 Warp 管理的密钥

Warp 在运行时将管理的密钥作为环境变量注入，从不在日志或配置文件中暴露它们。有关范围限定和管理密钥的完整详情，请参阅[密钥](/agent-platform/cloud-agents/secrets/)文档。

1. 运行以下命令：

```bash
oz secret create --team AZURE_DEVOPS_TOKEN
```

2. 提示时粘贴令牌。

值被存储和加密，创建后无法检索。

:::note
使用 `--team` 创建对所有团队成员和自动化触发器（计划、Slack、Linear）可用的共享令牌。如果每个团队成员应使用自己的 Azure DevOps 令牌进行身份验证，使用 `--personal`。个人密钥适用于所有触发器，并在两者都存在时优先于同名的团队密钥。
:::

如果需要更新密钥值，运行：

```bash
oz secret update --team --value AZURE_DEVOPS_TOKEN
```

---

## 第 3 步：使用克隆设置命令创建环境

创建一个在每次 agent 运行开始时使用令牌克隆仓库的环境。由于 `oz environment create` 中的 `--repo` 标志是为 GitHub 仓库设计的，您改为通过设置命令克隆 Azure DevOps 仓库。

1. 运行以下命令：

```bash
oz environment create \
  --name "my-azure-devops-env" \
  --docker-image <image> \
  --setup-command 'git clone https://$AZURE_DEVOPS_TOKEN@dev.azure.com/your-org/your-project/_git/your-repo' \
  --setup-command 'cd your-repo && <install dependencies>'
```

:::caution
在引用密钥的设置命令周围使用单引号。双引号会导致您的 shell 立即展开 `$AZURE_DEVOPS_TOKEN`（为空），而不是让 Warp 在运行时在容器内注入密钥。
:::

2. 替换以下占位符：
   * `<image>` 替换为您的 Docker 镜像（例如 `node:22`、`python:3.12` 或 [Warp 预构建开发镜像](https://github.com/warpdotdev/oz-dev-environments)）
   * `your-org` 替换为您的 Azure DevOps 组织名称
   * `your-project` 替换为您的 Azure DevOps 项目名称
   * `your-repo` 替换为您的仓库名称
   * 对于 Azure DevOps Server（自托管），将 `dev.azure.com` 替换为您的服务器主机名。
   * 第二个 `--setup-command` 替换为您的项目所需的任何依赖安装或构建步骤。例如，`npm ci` 或 `pip install -r requirements.txt`。

:::caution
设置命令在每次 agent 运行的干净容器上执行。将它们编写为幂等的——假设现有状态（如部分克隆的仓库或预构建的缓存）的命令可能不可预测地失败。请参阅[环境设计和最佳实践](/agent-platform/cloud-agents/environments/#environment-design-and-best-practices)获取指导。
:::

3. 记下返回的环境 ID。您在下一步中需要它。

---

## 第 4 步：测试您的环境

在连接到集成之前，通过运行一次性 agent 验证环境是否正常工作。

1. 运行以下命令，将 `<ENV_ID>` 替换为第 3 步中的环境 ID：

```bash
oz agent run-cloud --environment <ENV_ID> --prompt "Your task here"
```

---

## 后续步骤

环境配置完成后，您可以像使用 GitHub 支持的环境一样将其连接到任何 Warp 触发器：

* **Slack** — 在消息中标记 **@Oz** 以启动针对 Azure DevOps 仓库的 agent 运行。请参阅 [Slack](/agent-platform/cloud-agents/integrations/slack/)。
* **Linear** — 在问题上标记 **@Oz** 以启动工作流。请参阅 [Linear](/agent-platform/cloud-agents/integrations/linear/)。
* **计划 Agent** — 按重复计划运行 agent。请参阅[计划 Agent](/agent-platform/cloud-agents/triggers/scheduled-agents/)。

:::note
从 agent 生成的更改打开 Azure DevOps 拉取请求的原生支持已计划作为未来增强功能。
:::
