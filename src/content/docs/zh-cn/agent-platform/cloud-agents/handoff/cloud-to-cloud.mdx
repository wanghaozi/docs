Warp 中的云端到云端交接让您向已完成的云 agent 运行发送后续指令，并在新的云会话中继续。运行会保持相同的对话并恢复先前的工作区状态，因此 agent 可以从上次中断的地方继续，而不是从头开始。

观看此演示，了解云端到云端交接如何继续云 agent 运行而不丢失先前的会话上下文。

<VideoEmbed url="https://www.youtube.com/watch?v=tcYZy0D6dMA" title="什么是云端到云端交接？" />

在以下情况下使用此交接方向：

* 您希望在云 agent 的会话结束后向其发送后续指令。
* 您希望继续后台云 agent 运行，例如计划或集成触发的运行，同时将其保留为 [Warp 应用中的 Agent 管理面板](/agent-platform/cloud-agents/managing-cloud-agents/)和 [Oz Web 应用中的 Runs 页面](/agent-platform/cloud-agents/oz-web-app/#runs)中的单一工作单元。

## 延续的内容

当您向会话已结束的运行发送后续指令时，运行会继续：

* **相同的对话** - 后续指令追加到同一对话中。从您的角度来看，运行是跨会话的一个连续对话。
* **先前的工作区状态** - 先将会话的仓库更改（已跟踪和未跟踪）在 agent 回答您的后续指令前恢复。对于 Git 管理的会话，新会话在相同的 Git 分支上继续。您可以在打包的云 agent 映像之外运行时[自定义哪些仓库和文件被快照](/agent-platform/cloud-agents/handoff/snapshots/)。
* **稳定的运行身份** - 运行的 ID、任务、创建者、环境、计划触发器和集成来源都会被保留。计算用量按会话记录，但汇总到同一运行。

如果有任何更改应用失败，agent 会报告哪些更改失败，并继续处理已成功应用的更改。

## 前提条件

* **一个已结束的云 agent 运行** - 运行必须处于终端状态，如成功、失败或取消，并具有关联的 agent 对话。正在等待用户输入或批准的阻塞运行无法通过云端到云端交接继续；直接在原始运行上响应提示。早于 agent 对话模型的非常老的运行无法通过交接继续。
* **来自先前会话的快照** - 云 agent 运行在每个会话结束时捕获工作区快照。如果先前会话无法捕获（例如由于暂时存储错误），运行仍会继续，但没有恢复的工作区状态。
* **访问运行** - 您需要提交运行后续指令的权限。对于团队运行，通常任何团队成员都可以。源自本地到云端交接的云运行只能由创建它们的用户继续，不能由其他团队成员继续。

:::caution
云端到云端交接依赖于先前会话的快照。没有快照文件的旧云运行无法交接；请改为开始新运行。
:::

## 发送后续指令

要继续已结束的云运行，在 Warp 中打开该运行并发送对话中的下一条消息。当原始会话已结束时，Warp 会自动启动新的云会话并恢复先前的工作区状态。

1. **打开已结束的云运行。** 在 Oz Web 应用的 [Runs 页面](https://oz.warp.dev/runs) 或 Warp 应用的对话面板中找到它。
2. **发送您的后续指令。** 在对话的输入中输入下一条消息并提交。

运行从上次中断的地方继续，工作区状态已恢复。

### 第三方 agent 运行时

云端到云端交接也适用于受支持的第三方 agent 运行时，但流程与 Warp Agent 运行略有不同：

1. 从 Warp 应用的对话面板或运行完成后显示的制品中打开已结束的运行。
2. 点击**继续**。
3. 输入您的后续提示并提交。

## 检查已交接的运行

Warp 应用中的 [Agent 管理面板](/agent-platform/cloud-agents/managing-cloud-agents/)和 Oz Web 应用中的 [Runs 页面](/agent-platform/cloud-agents/oz-web-app/#runs)显示每次运行一行，即使运行跨越多个会话。

1. 打开 Warp 应用中的 [Agent 管理面板](/agent-platform/cloud-agents/managing-cloud-agents/)或 Oz Web 应用中的 [Runs 页面](/agent-platform/cloud-agents/oz-web-app/#runs)。
2. 选择已交接的运行。
3. 审查记录。每个会话按顺序出现，因此您可以看到一个会话结束和下一个会话开始的位置。

每个会话的时间戳目前未在 API 中公开；记录是唯一信息来源。

## 故障排除

**运行继续了，但没有恢复工作区状态。**
先前的会话没有捕获快照。这很少见，但可能发生，因为快照捕获是尽力而为的。运行仍会以相同的对话继续，因此即使没有工作区状态，agent 也有完整的记录上下文。

**运行处于终端状态但没有对话，后续指令被拒绝。**
非常老的运行早于 agent 对话模型，无法通过交接继续。使用您想要的提示启动新的云 agent 运行，并在需要时引用先前的运行。
