标签配置允许您在简单的 TOML 文件中定义可重用的标签设置——包括目录、启动命令、窗格布局、shell 和主题。从 `+` 菜单中选择一个标签配置，即可一键打开一个完全配置好的标签。

<VideoEmbed url="https://youtu.be/Bq30S3wIpOU" title="Warp 中的标签配置" />

## 标签配置的工作原理

每个标签配置都是一个存储在 Warp 的 `tab_configs` 目录中的 `.toml` 文件。每个文件定义一个单一的标签布局，可选配窗格拆分、启动命令和参数化输入。标签配置出现在 `+` 菜单中，旁边是您现有的标签，因此您可以即时启动预配置的工作区。

`tab_configs` 目录在每个平台上位于不同的位置：

<Tabs>
  <TabItem label="macOS">
    `~/.warp/tab_configs/`（Stable）或 `~/.warp-preview/tab_configs/`（Preview）。
  </TabItem>
  <TabItem label="Windows">
    `%APPDATA%\warp\Warp\data\tab_configs\`（Stable）或 `%APPDATA%\warp\WarpPreview\data\tab_configs\`（Preview）。
  </TabItem>
  <TabItem label="Linux">
    `${XDG_DATA_HOME:-$HOME/.local/share}/warp-terminal/tab_configs/`（Stable）或 `${XDG_DATA_HOME:-$HOME/.local/share}/warp-terminal-preview/tab_configs/`（Preview）。
  </TabItem>
</Tabs>

有关 Warp 文件位置的完整列表，请参见 [文件和文件夹位置](/terminal/settings/file-locations/)。

## 创建标签配置

### 从 UI

1. 点击标签栏中的 **+** 按钮打开新标签菜单。
2. 点击 **+ 新建标签配置**。Warp 在 `tab_configs` 目录中创建一个新的 `.toml` 文件并打开它进行编辑。

### 手动

1. 在上述 `tab_configs` 目录中创建一个新的 `.toml` 文件。使用蛇形命名法作为文件名（例如 `dev_server.toml`）。
2. 使用下面的模式定义标签布局，然后保存文件。新的配置会自动出现在 `+` 菜单中。

### 将现有标签另存为标签配置

您还可以将标签的当前状态捕获为可重用的标签配置，而无需编写 TOML。右键单击 [垂直标签](/terminal/windows/vertical-tabs/) 面板或水平标签栏中的任何标签以打开上下文菜单，然后点击 **另存为新配置**。Warp 从标签的布局、命令和目录生成一个 `.toml` 文件，并将其添加到 `+` 菜单中。

## 管理标签配置

已保存的标签配置出现在 `+` 菜单中以供快速访问。当您在菜单中悬停一个标签配置时，其旁边会出现一个 **侧边面板**，其中包含以下选项：

* **编辑配置** — 打开底层的 `.toml` 文件进行手动编辑。编辑器还会显示一个页脚来调用"更新标签配置"技能，因此您可以用自然语言描述更改，让 Warp 的代理应用它们。
* **移除** — 从 `+` 菜单中移除标签配置。
* **设为默认** — 将标签配置分配为默认的 `Cmd T` 新标签操作。

## 从 URL 打开标签配置

您可以通过 Warp 的 [URI 方案](/terminal/more-features/uri-scheme/) 直接打开已保存的标签配置。这对于浏览器书签、脚本和启动器（如 Raycast 或 Alfred）非常有用，它们需要直接跳转到已配置的窗格布局，而无需通过 `+` 菜单。

默认情况下，标签配置在活动窗口中作为新标签打开。传递 `?new_window=true`（或在没有 Warp 窗口打开时调用）以在新窗口中打开它。

```bash
# 在聚焦窗口中打开 my_tab.toml 作为新标签
open "warp://tab_config/my_tab"

# 在全新窗口中打开它
open "warp://tab_config/my_tab?new_window=true"
```

`<name>` 不区分大小写地匹配 `.toml` 的文件名（不含扩展名），因此 `warp://tab_config/my_tab` 和 `warp://tab_config/my_tab.toml` 都解析为 `my_tab.toml`。匹配使用文件名而不是文件内的 `name` 字段，因为多个标签配置可以共享相同的显示名称。

如果标签配置声明了 `[params.*]` 条目，则参数模态框会像从 `+` 菜单启动一样打开。引用 `{{autogenerated_branch_name}}` 的工作树风格配置每次打开时仍然会获得一个新生成的分支名称。

:::note
在 Warp Preview 上，请改用 `warppreview://tab_config/<name>`。
:::

## 使用技能管理标签配置

Warp 包含用于通过自然语言创建和修改标签配置的内置技能：

* **创建标签配置** — 从描述生成新的标签配置（例如"创建一个 2x2 网格，其中一个窗格运行我的开发服务器"）。
* **更新标签配置** — 通过描述您想要的更改来修改现有的标签配置。

要使用这些技能，在代理模式中输入 `/skills` 并选择标签配置技能，或使用编辑标签配置文件时出现的页脚。

## 标签配置 TOML 模式

### 顶层字段

* **`name`**（必填，string）— 在 `+` 菜单中显示的显示名称。
* **`title`**（可选，string）— 自定义标签标题。支持 `{{param}}` 模板变量。
* **`color`**（可选，string）— 标签颜色。可选值：`"black"`、`"red"`、`"green"`、`"yellow"`、`"blue"`、`"magenta"`、`"cyan"`、`"white"`。实际颜色值来自您的 Warp [主题](/terminal/appearance/themes/)。

### 窗格列表

所有窗格都在一个扁平的 `[[panes]]` 数组中定义。第一个条目是窗格树的根。每个条目要么是 **拆分节点**（分支），要么是 **叶子节点**。

#### 叶子节点字段

* **`id`**（必填，string）— 此窗格的唯一标识符。使用描述性名称，如 `"editor"` 或 `"server"`。
* **`type`**（必填，string）— `"terminal"`（标准 shell）、`"agent"`（在代理模式下打开）或 `"cloud"`（云模式窗格，无本地 shell）。
* **`directory`**（可选，string）— 初始工作目录。支持 `~` 展开和 `{{param}}` 模板变量。
* **`commands`**（可选，字符串数组）— 标签打开时按顺序运行的命令。
* **`shell`**（可选，string）— 此窗格使用的 shell 可执行文件（例如 `"pwsh"`、`"zsh"`、`"bash"`、`"fish"`）。仅适用于 `terminal` 和 `agent` 窗格类型。如果省略或指定的 shell 未安装，则使用用户的默认 shell。
* **`is_focused`**（可选，bool）— 最多在一个窗格上设置为 `true`，为其提供初始焦点。

#### 拆分节点字段

* **`id`**（必填，string）— 此拆分的唯一标识符。
* **`split`**（必填，string）— `"horizontal"`（子元素从左到右排列）或 `"vertical"`（子元素从上到下排列）。
* **`children`**（必填，字符串数组）— 子窗格 `id` 值的有序列表。必须至少包含 2 个条目。顺序决定视觉顺序。

:::note
拆分中的所有子窗格大小相等。没有 flex 或比例值。
:::

### 参数

参数允许用户在打开时通过模态提示填写值。使用 `[params.<name>]` 表声明它们，并使用 `{{name}}` 语法在 `directory`、`commands` 和 `title` 中引用它们。

每个参数都有：

* **`type`**（可选，string）— `"text"`（默认，自由输入）、`"branch"`（Git 分支选择器）或 `"repo"`（仓库选择器）。
* **`description`**（可选，string）— 在填写界面中显示的标签。
* **`default`**（可选，string）— 默认值。

`{{autogenerated_branch_name}}` 是一个保留的模板变量。如果标签配置引用了它，Warp 会在每次打开时生成一个唯一的工作树分支名称，而不是提示用户。

## 示例

### 单窗格

一个简单的配置，在项目目录中打开一个终端并启动开发服务器：

```toml
name = "Dev Server"

[[panes]]
id = "main"
type = "terminal"
directory = "~/code/my-app"
commands = ["npm run dev"]
```

### 两个并排窗格

一个编辑器和服务器并行运行，编辑器获得焦点：

```toml
name = "Editor + Server"
color = "green"

[[panes]]
id = "root"
split = "horizontal"
children = ["editor", "server"]

[[panes]]
id = "editor"
type = "terminal"
directory = "~/code/my-app"
commands = ["nvim ."]
is_focused = true

[[panes]]
id = "server"
type = "terminal"
directory = "~/code/my-app"
commands = ["npm run dev"]
```

### 跨 shell 开发

一个配置，打开两个并排窗格，每个使用不同的 shell：

```toml
name = "Cross Shell"
color = "cyan"

[[panes]]
id = "root"
split = "horizontal"
children = ["bash_pane", "pwsh_pane"]

[[panes]]
id = "bash_pane"
type = "terminal"
shell = "bash"
directory = "~/code/my-app"
is_focused = true

[[panes]]
id = "pwsh_pane"
type = "terminal"
shell = "pwsh"
directory = "~/code/my-app"
```

### 带参数的工作树

一个参数化配置，在打开时创建新的 Git 工作树：

```toml
name = "New Worktree"
title = "{{branch_name}}"

[[panes]]
id = "main"
type = "terminal"
directory = "{{repo}}"
commands = [
  "git worktree add -b {{branch_name}} ../{{branch_name}} {{base_branch}}",
  "cd ../{{branch_name}}",
]

[params.repo]
type = "repo"
description = "仓库路径"

[params.base_branch]
type = "branch"
description = "要创建分支的基础分支"

[params.branch_name]
type = "text"
description = "新分支名称"
default = "my-feature"
```

### 快速工作树设置

您还可以直接从 `+` 菜单通过点击 **新建工作树配置** 并选择您希望工作树来自的仓库来创建基于工作树的标签配置。Warp 会自动生成标签配置并保存以供将来使用。
