Warp 原生支持 [Git 工作树](https://git-scm.com/docs/git-worktree)——一个 Git 功能，允许你在单独的目录中同时检出多个分支，所有这些都由同一个仓库支持。这与简单地切换分支不同：使用工作树，你可以同时在 `~/project` 上使用 `main` 分支，在 `~/project-wt/feature-x` 上使用 `feature-x` 分支，无需暂存或上下文切换。

## 工作树在 Warp 中的工作方式

Warp 自动检测工作树检出。当你在工作树目录中打开终端时，Warp 会识别指向主仓库的 `.git` 文件，并将工作树视为一个功能完整的仓库：

* **代码审查面板** — 每个工作树都有自己的代码审查面板，显示该工作树分支的未提交更改。你可以独立地在每个工作树中审查差异、还原块和放弃更改。
* **Git 状态标签** — 输入栏中的 Git diff 标签和分支指示器会反映你终端所在工作树的正确分支和更改计数。
* **文件监视** — Warp 同时监视工作树的工作目录和共享的 `.git` 目录。共享 Git 状态的更改（例如推送到远程的新提交）会被检测到并传播到所有打开的工作树。
* **代码库上下文** — 每个工作树都独立索引用于[代码库上下文](/agent-platform/capabilities/codebase-context/)，因此智能体对于你正在工作的任何工作树都有准确的上下文。
* **仓库范围的功能** — 项目规则（`AGENTS.md`、`WARP.md`）、忽略文件和其他仓库范围的设置在每个工作树中都能正确工作。

## 何时使用工作树

工作树在以下情况下特别有用：

* **在自己的分支上工作时审查 PR** — 在单独的工作树中打开 PR 分支，不会干扰你正在进行的工作。
* **在一个分支上运行测试，同时在另一个分支上编码** — 在一个工作树中保持长时间的测试套件运行，同时在另一个工作树中继续开发。
* **并行本地智能体工作** — 当在同一仓库上编排多个本地智能体时，每个智能体可以在自己的工作树中操作，以避免文件冲突。

## 创建工作树

要从终端创建一个新的工作树：

```bash
# 为现有分支创建工作树
git worktree add ../my-feature feature-branch

# 使用新分支创建工作树
git worktree add -b new-branch ../new-branch main

# 列出所有工作树
git worktree list

# 完成后删除工作树
git worktree remove ../my-feature
```

创建后，在新 Warp 标签页或窗格中打开工作树目录。Warp 会自动检测它——无需额外配置。

:::note
提交状态更改通知（例如检测新提交）在工作树中可能比标准仓库稍有延迟。Warp 正在积极改进这一点。
:::
