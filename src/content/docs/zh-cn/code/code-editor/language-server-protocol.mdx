Warp 的代码编辑器内置了对[语言服务器协议](https://microsoft.github.io/language-server-protocol/)的支持，为你提供直接在终端中的 IDE 级别代码智能。当你为项目启用 LSP 服务器时，你将获得悬停文档、转到定义、查找引用、内联诊断和自动格式化——全部无需离开 Warp。

## 支持的语言

Warp 内置了对以下语言服务器的支持：

| 语言 | 服务器 | 文件扩展名 |
| --- | --- | --- |
| Rust | `rust-analyzer` | `.rs` |
| Go | `gopls` | `.go` |
| Python | `pyright` | `.py` |
| TypeScript / JavaScript | `typescript-language-server` | `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs` |
| C / C++ | `clangd` | `.c`, `.C`, `.h`, `.H`, `.hh`, `.cc`, `.cpp`, `.cxx`, `.hpp`, `.hxx` |

我们正在积极扩展语言支持。要请求一门语言，请[提交 GitHub issue](https://github.com/warpdotdev/Warp/issues)。

## 工作原理

当你 `cd` 到启用了语言服务器的工作空间中时，Warp 会自动在后台启动它们。一旦服务器完成初始化，悬停、诊断和转到定义等功能就可用。当你编辑时，Warp 会发送增量更新以保持一切同步。如果你关闭某个工作空间的所有文件和终端，Warp 会关闭空闲的服务器以释放资源。

:::note
Warp 使用你的 shell 的 `PATH` 来定位语言服务器二进制文件。如果在你的 `PATH` 上找不到服务器，Warp 可以为你安装它（请参阅下面的[启用服务器](#启用服务器)）。
:::

## 启用和管理语言服务器

### 启用服务器

语言服务器是**按工作空间**（按 Git 仓库根目录）启用的。当你首次打开一个支持的语言的文件时，**编辑器页脚**会显示启用相应语言服务器的选项。如果服务器二进制文件未在你的系统上安装，Warp 会提供为你安装。

你也可以从**设置** > **代码** > **索引和项目**管理服务器，每个已初始化的工作空间都会显示其启用的语言服务器及其状态。

### 服务器状态指示器

代码编辑器页脚显示活动语言服务器的状态图标：

* 🟢 **绿色** - 服务器正在运行并准备就绪。
* 🟡 **黄色** - 服务器正在启动或处理后台任务。
* 🔴 **红色** - 服务器启动失败。点击图标查看选项。
* ⚪ **灰色** - 服务器已停止。

点击状态图标会打开一个菜单，其中包含**重启**、**停止**、**启动**或**查看日志**的选项。

### 服务器日志

每个语言服务器都会将日志写入磁盘上的文件。你可以从页脚菜单（点击状态图标并选择"打开日志"）或从**设置** > **代码** > **索引和项目**访问这些日志。日志对于调试服务器启动失败或意外行为非常有用。

## LSP 驱动的编辑器功能

### 悬停信息

悬停在某个符号上以查看其类型签名、文档以及语言服务器提供的其他详细信息。悬停工具提示会在短暂延迟后显示，并支持包含代码块和 Markdown 的富文本内容。

### 转到定义

按住 `CMD`（macOS）或 `CTRL`（Windows/Linux）并点击某个符号以跳转到其定义。如果定义在另一个文件中，Warp 会在代码编辑器中打开它。当你按住修饰键时，符号在悬停时会被加下划线，表示它可以导航。

### 查找引用

在已处于其定义位置的符号上执行 `CMD`-点击（macOS）或 `CTRL`-点击（Windows/Linux），查看一个**查找引用**卡片，列出工作空间中所有引用。点击任何引用以导航到它。

### 内联诊断

Warp 在编辑器中直接以虚线下划线显示来自语言服务器的错误和警告。悬停在下划线范围上以查看完整的诊断消息。诊断在你编辑时实时更新，并在服务器重新计算时短暂清除。

### 保存时格式化

当你保存文件（`CMD + S` / `CTRL + S`）时，Warp 在写入磁盘之前向语言服务器请求格式化。这会应用服务器配置的格式化规则（缩进、尾随空白、最终换行符等）。如果服务器不支持格式化，文件将在没有格式化更改的情况下保存。

### 右键上下文菜单

当 LSP 服务器连接后，在编辑器中右键单击会打开一个包含 LSP 驱动操作的上下文菜单，包括转到定义和查找引用。

LSP 功能在[共享缓冲区](/code/code-editor/#shared-buffers)之间保持同步——如果同一文件在多个标签页或窗格中打开，诊断、悬停和其他功能无论你查看哪个视图都反映相同的内容。

## 限制

* **仅限本地会话** - LSP 在 SSH 或 WSL 会话中不可用。这些在 GitHub issues [#6831](https://github.com/warpdotdev/Warp/issues/6831) (SSH) 和 [#6744](https://github.com/warpdotdev/Warp/issues/6744) (WSL) 中跟踪。
* **每种语言一个服务器** - 每种语言映射到一个服务器（例如 Rust 始终使用 `rust-analyzer`）。尚不支持自定义服务器配置。
* **项目范围** - 语言服务器在 Git 仓库根目录级别运行。仓库之外的文件可能无法获得 LSP 功能。
* **服务器可用性** - 某些功能（如格式化）取决于特定语言服务器的能力。并非所有服务器都支持所有功能。
