当你[Warpify 一个 SSH 会话](/terminal/warpify/ssh/)时，Warp 的核心终端功能——输入编辑器、补全、块、历史搜索等——与本地使用时的表现相同。在远程主机上安装了 Warp 的 [SSH 扩展](/terminal/warpify/ssh/#installing-the-ssh-extension)后，其他编码功能（如文件树、原生文件读取和原生代码差异）也可以在 macOS 和 Linux 上的 SSH 会话中使用。

此页面记录了基于你所处的路径可用的功能：

* **SSH 扩展** - 在你选择**安装 Warp 的 SSH 扩展**时，首次连接时安装。在 macOS 和 Linux 远程主机上可用。
* **传统的基于 tmux 的 Warpification** - 一个正在弃用的旧替代方案。对于尚未提供 SSH 扩展的客户端（例如 Windows 客户端），它今天仍然可用。请参阅[传统：基于 tmux 的 Warpification](/terminal/warpify/ssh/#legacy-tmux-based-warpification)。

:::note
当当前路径上不可用原生工具时，智能体会回退到终端命令（例如 `cat`、`sed`、`grep`）。你仍然可以完成大多数编码任务，但体验不如本地工作或通过 SSH 扩展时无缝。
:::

## 在 SSH 上工作的功能

以下功能在两条路径上的 Warpified 远程会话中都可以工作：

* **智能体模式对话** — 与智能体聊天、提问以及在远程主机上请求代码更改。
* **运行 shell 命令** — 智能体可以代表你在远程机器上执行命令。
* **Grep 和文件通配** — 智能体可以使用基于终端的 grep 和通配工具搜索文件和模式。
* **MCP 工具** — 模型上下文协议集成仍然可用。
* **终端功能** — 输入编辑器、命令补全、自动建议、命令历史、块以及所有其他核心终端功能按预期工作。

以下功能需要 **SSH 扩展**：

* **文件树（项目浏览器）** — [文件树侧边栏](/code/code-editor/file-tree/)反映远程项目结构，并在你导航或更改文件时更新。
* **原生文件读取** — 智能体通过 Warp 内置的文件读取工具读取远程文件，而不是调用 `cat`。
* **原生代码差异** — 智能体将编辑应用为你可以审查和批准的内联[代码差异](/agent-platform/local-agents/code-diffs/)，而不是使用 `sed` 或其他 shell 命令。
* **可靠、并行的补全** — 生成器通过单一多路复用连接并行运行，因此补全不再触及远程主机的 `MaxSessions` 上限，也不再偶尔将错误注入你的块中。

## 尚不支持 SSH 的功能

以下功能需要本地文件系统访问，在两条路径上的 Warpified 远程（SSH）会话中尚不可用：

* **代码编辑器（文件打开/编辑 UI）** — Warp 的[原生代码编辑器](/code/code-editor/)在远程会话中尚不可用。你无法在 Warp 内置编辑器中打开、查看或编辑远程文件。
* **计算机使用** — 智能体无法截图或与远程机器的桌面交互。

:::note
WSL 会话与 SSH 具有相同的限制，目前未包含在 SSH 扩展中。WSL 支持的功能请求：[GitHub #6744](https://github.com/warpdotdev/Warp/issues/6744)。
:::
