### 什么是 Warp 积分？

与 Warp 代理的任何交互都会消耗积分。积分主要基于 AI 使用量——任务消耗的积分数量根据代码库的大小和复杂度、任务的大小、您使用的模型、代理需要收集的上下文量等因素而变化。

Warp 在三种类型的基础设施之间计量积分——推理、计算和平台——每种类型有自己的桶。积分类型和代理运行位置（本地或云端）是独立的：每次代理运行消耗适用于它的任意积分类型。

* **AI 积分**涵盖推理：LLM 调用本身。当 Warp 通过 Warp 管理的提供商支付模型调用时消耗。
* **计算积分**涵盖计算：代理运行所在的沙箱。当代理运行使用 Warp 托管的计算资源时消耗。实际上这是云代理运行；本地代理运行使用您自己的机器，不消耗计算积分。请参阅[计算积分](/support-and-community/plans-and-billing/credits/#compute-credits)。
* **平台积分**涵盖 Warp 的平台层：运行生命周期、集成、仪表板、API 和可观测性。适用于每次云代理运行，以及使用客户提供的推理（BYOK、自定义推理端点或 BYOLLM）的 Business 和 Enterprise 计划的本地代理运行。请参阅[平台积分](/support-and-community/plans-and-billing/platform-credits/)。

所有三个桶都从同一个 Warp 积分池和[附加积分](/support-and-community/plans-and-billing/add-on-credits/)中扣除，因此您可以在 Warp 应用中的**设置** > **账单和使用情况**中将其作为单一余额进行管理。

每次交互消耗**至少一个积分**，不过更复杂的交互可能使用**多个积分**。由于代码库大小、模型选择、工具调用次数以及 LLM 的特性等因素，积分使用是**非确定性的**——两个相似的提示可能使用不同数量的积分。

:::note
关于哪些因素影响积分消耗的一般性说明，请参阅：[Warp 积分是如何计算的？](/support-and-community/plans-and-billing/credits/#how-are-warp-credits-calculated)
:::

#### 积分**限制和计费**

* **席位级分配**：在团队计划上，积分限制按席位应用——每个团队成员有自己的配额。个人用户（非团队成员）也有自己的积分分配。
* **云代理和集成**：个人用户可以通过 CLI 和 API 运行云代理，从他们的 Warp 积分中扣除。Slack 和 Linear 集成需要团队成员资格。
* **达到积分限制**：一旦达到月度积分限制，您的访问权限将取决于您的计划。在 Free 计划上，AI 访问会停止，直到下一个计费周期。在付费计划上，您可以通过[附加积分](/support-and-community/plans-and-billing/add-on-credits/)的按用量计费继续使用 AI。

#### **其他使用积分的功能**

除了直接的代理对话外，以下功能也会消耗积分：

* [生成](/agent-platform/local-agents/overview/)帮助您在输入时查找命令和建议。当您细化输入时，在选择最终建议之前可能会使用多个积分。
* [工作流中的 AI 自动填充](/knowledge-and-collaboration/warp-drive/workflows/#ai-autofill)每次运行时消耗一个积分。

:::tip
Warp 中的常规 shell 命令不消耗或计入积分。
:::

### Warp 积分是如何计算的？

Warp 中的**积分**是工作单位，代表完成与代理交互所需的总处理量。它**不等同于**"一条用户消息"——而是与交互期间处理的令牌数量成正比。

简而言之：**使用的令牌越多，消耗的积分越多**。

影响单次交互计分数的几个因素：

#### **1. 使用的 LLM 模型**

通常，较小的快速模型消耗的积分通常少于较大的推理模型。

例如，**Claude Opus 4.7** 在 Warp 中消耗的令牌和积分最多，其次是 **Claude Sonnet 4.6、GPT-5.5、Gemini 3.1 Pro** 等，大致按此顺序。这通常也与模型定价相关。

:::note
**提示**：如果您的任务不需要深度推理、规划或多步骤问题解决，请选择更轻量的模型以减少积分使用。
:::

#### 2. 代理触发的工具调用

Warp 代理会进行各种工具调用，包括：

* 搜索文件（grep）
* 检索和读取文件
* 制作和应用代码差异
* 收集网页或文档上下文
* 运行其他工具

某些提示只需要几次工具调用，而其他可能需要多次——特别是如果代理需要探索您的开发环境、浏览大型代码库或应用复杂更改。**工具调用越多 = 积分越多**。

#### 3. 任务复杂性和步骤数

某些任务很简单，可能只需要一次快速响应，无需太多思考或推理。其他可能涉及多个阶段——例如规划、生成中间输出、验证结果、应用更改和自我修正——每个阶段都可能增加积分计数。

:::note
**提示**：保持给代理的任务范围明确，增量工作，将大变更分解为更小的、独立的步骤。
:::

#### 4. 传递给模型的上下文量

包含大量上下文的提示（如[附加的块](/agent-platform/local-agents/agent-context/blocks-as-context/)、长用户查询消息等）或文件附件（如[图片](/agent-platform/local-agents/agent-context/images-as-context/)）也可能由于令牌消耗增加而增加使用的积分数量。

:::note
**提示**：分享日志、代码或其他大段内容时，只附加最相关的部分，而不是完整的输出。
:::

#### 5. 提示缓存（命中与未命中）

许多模型提示包含重复的内容，如系统指令：

* **缓存命中**：如果模型提供者能够匹配过往请求中的前缀或部分内容，它可以重用缓存中的结果，减少消耗的令牌和延迟。
* **缓存未命中**：如果未找到匹配项，可能需要重新处理完整提示，这可能增加积分消耗。

由于缓存结果取决于模型提供者的行为和时机，两个相似的提示可能仍具有不同的积分计数，具体取决于您运行命令的时间。

:::note
**提示**：尽可能在连续的会话中工作，以提高缓存命中率。
:::

这些是影响积分使用的最常见因素，但还有其他因素。了解这些因素可以帮助您更有效地管理积分，充分利用您的计划。

### 计算积分

计算积分涵盖代理运行所消耗的 Warp 托管计算资源。实际上，云代理运行会消耗它们，因为它们在 Warp 的计算资源上运行；本地代理运行通常不会，因为它们在您自己的机器上运行。

当对话围绕云代理与本地代理展开时，计算积分有时被称为**云代理积分**——它们是同一个桶，只是从不同角度描述。

#### 消耗计算积分的场景

以下场景使用计算积分：

* **第一方集成** - 通过 Slack 或 Linear 集成运行代理
* **云代理运行** - 通过 CLI 使用 `oz agent run-cloud`
* **Oz API** - 通过 Warp 的 Oz API 运行代理
* **云模式** - 在 Warp 应用中从云模式运行代理

#### 不消耗计算积分的场景

* **本地代理运行** — 在本地机器上使用 `oz agent run`
* **自托管计算** — 在 GitHub Actions、CI/CD 流水线或其他自托管基础设施上使用 `oz agent run`

### 平台积分

平台积分涵盖 Warp 的平台基础设施——运行生命周期、调度、集成、仪表板、API 和可观测性——用于每次云代理运行，以及使用客户提供推理的 Business 和 Enterprise 计划的本地代理运行。

#### 消耗平台积分的场景

平台积分在以下场景中使用：

* **任何计划上的云代理**每次云代理运行都会使用平台积分，无论哪个代理运行任务或使用哪个推理源。
* **使用客户提供推理的 Business 或 Enterprise 本地代理**当本地代理运行使用[自带 API 密钥 (BYOK)](/agent-platform/inference/bring-your-own-api-key/)、[自定义推理端点](/agent-platform/inference/custom-inference-endpoint/)或[BYOLLM](/enterprise/enterprise-features/bring-your-own-llm/)时会消耗平台积分。

#### 不消耗平台积分的场景

以下场景**不**使用平台积分：

* **Free、Build 或 Max 计划上的本地代理**不消耗平台积分，无论推理源是什么。
* **使用 Warp 管理推理的 Business 或 Enterprise 本地代理**不消耗平台积分，因为 Warp 已经通过 AI 积分支付了模型调用费用。
* **常规终端使用**不消耗平台积分。Shell 命令和非 AI 的 Warp 功能不消耗积分。
* **直接运行的第三方代理 CLI**当您在 Oz 之外直接运行 `claude`、`codex` 或其他代理 CLI 时不消耗平台积分。

有关平台积分如何运作的完整说明，请参阅[平台积分](/support-and-community/plans-and-billing/platform-credits/)。

### 团队计划上的云代理运行

并非由特定团队成员发起的云代理运行——例如计划运行或通过团队 API 密钥触发的运行——遵循特定于计划的计费规则。在自助计划（Build、Max、Business）上，这些运行向**团队所有者**计费：首先使用所有者的计划包含积分，然后使用其附加积分。自动充值关闭时，当两个池都用尽时请求将被阻止（积分不足错误）。自动充值开启时，使用量可能触发所有者池的自动充值，受团队支出上限约束。在 Enterprise 计划上，这些运行根据您的合同从团队范围的积分池中扣除。

有关完整的级联流程，请参阅定价常见问题中的[团队计划中未由个人用户触发的云代理运行如何计费？](/support-and-community/plans-and-billing/pricing-faqs/#how-are-cloud-agent-runs-on-team-plans-billed-when-no-individual-user-triggered-them)
