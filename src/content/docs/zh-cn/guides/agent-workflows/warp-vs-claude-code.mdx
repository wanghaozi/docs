### 1. 概述

本演练比较了 Claude Code 和 Warp 的内置编码代理——两款专为 AI 辅助开发构建的工具。\
两者都可以：

* 读取和编辑文件
* 生成代码差异
* 规划多步骤任务\
  \
  但它们在体验、可配置性和性能上有所不同。

---

### 2. 设置和界面

#### Claude Code

* 作为 CLI 工具运行，需要终端并安装 `claude` CLI。
* 直接在命令框中输入提示词。
* 支持文件读取、搜索和差异生成。

#### Warp

* 直接内置于 Warp 终端中。
* 无需安装——输入自然语言查询或点击代理按钮进入代理模式。
* 执行与 Claude Code 相同的操作，但集成在你已经使用的环境中。

---

### 3. 审查差异

在 Claude Code 中：

* 通过 CLI 或 VS Code 等外部编辑器手动审查差异。
* 可以按 Shift + Tab 自动接受所有编辑。

在 Warp 中：

* 内置可视化差异视图。
* 可以使用 Warp 的轻量级编辑器接受、拒绝或手动内联编辑差异。
* 代理自动更新其上下文以避免覆盖你的更改。

---

### 4. 规划和上下文收集

两者都支持复杂任务的规划模式：

* Claude Code 使用 Markdown 风格的规划视图。
* Warp 可以显示类似的计划，或对短任务跳过规划。

关于上下文：

* 两者都允许使用 `@filename` 引用文件。
* Warp 在此基础上增加了符号引用（`@functionName`）和文件树浏览器，让你可以提取特定行和符号作为上下文。

---

### 5. 模型选择

Claude Code 允许你通过 `/model` 菜单在 Claude 3 模型（`Sonnet`、`Opus`、`Haiku`）之间选择。

Warp 支持多个生态系统：

* Claude（Sonnet、Opus）
* GPT-5（不同推理级别）
* Gemini 系列

通过下拉菜单或直接在代理菜单中切换模型。

---

### 6. 配置

在 Claude Code 中：

* 所有内容通过 CLI 中的 `/commands` 配置。
* 包括模型切换、工具权限和子代理创建。

在 Warp 中：

* 从设置 → AI 和代理中配置。
* 添加 MCP 服务器、提示词和全局规则。
* 定义代理配置文件以管理读/写权限、自主性和规划行为。
* 维护全局规则目录，确保跨项目的一致行为。

Warp 还支持代码库索引，通过创建嵌入实现跨仓库的更快速语义搜索。

---

### 7. 长期管理代理

Claude Code：

* 直接在 CLI 标签中显示进度。
* 在终端标签标题中显示当前任务名称。

Warp：

* 添加代理状态、进度的视觉指示器，以及被阻塞时的 Toast 通知。
* 可选的桌面通知让你在多任务时也能了解情况。

---

### 8. 性能比较

Ben 在两个工具上运行了相同的编码任务——修复来自 Sentry 问题的 `renderKeyboardShortcut` 函数中的错误。

Claude Code 结果：

* 使用 Claude 3 Sonnet 耗时约 2-4 分钟。
* 找到了正确的问题并生成了可工作的代码，但存在一些冗余逻辑。

Warp 结果：

* 使用 GPT-5，平均时间约 1 分 20 秒。
* 一致、高质量的输出。
* 生成的解决方案简洁，冗余检查更少。
* 支持多种模型进行实验。

---

### 9. 结论

| 标准 | Claude Code | Warp |
| --------------- | ----------------- | ------------------------ |
| 环境 | CLI 工具 | 集成到终端中 |
| 差异审查 | 外部/手动 | 内置面板 |
| 规划 | Markdown 模式 | 内联或 Opus 辅助 |
| 模型选项 | 仅限 Claude | Claude、GPT-5、Gemini |
| 可配置性 | 基于 CLI | UI + 配置文件 + 规则 |
| 性能 | 平均 2-4 分钟 | 平均约 1.2 分钟（GPT-5） |

**总结：**\
如果你更喜欢 Claude 模型套件和 CLI 工作流——选择 Claude Code。\
如果你想要更丰富的差异编辑、上下文引用和模型灵活性——Warp 是更好的选择。

> "Claude Code 给你一个 AI 终端。Warp 给你一个 AI 开发环境。"
