Warp 云端代理可以从定时任务、团队工具、CI、Oz CLI 或 API 无人值守运行。当你希望代理在离开终端后继续工作、响应外部事件或运行重复性维护而无需人为启动每次运行时，可以使用它们。

每个无人值守工作流都会创建一个云端代理运行，你的团队可以在之后检查。从 [Oz Web 应用中的 Runs 页面](/agent-platform/cloud-agents/oz-web-app/#runs)、Warp 应用中的[代理管理面板](/agent-platform/cloud-agents/managing-cloud-agents/)或发布回触发代理的工具的会话链接中打开运行。

## 选择触发器

使用此表格决定无人值守代理应在何处启动。

| 触发器 | 何时使用 | 配置位置 | 检查位置 |
| ------- | ----------- | ------------------ | ---------------- |
| 定时代理 | 工作应按照可预测的节奏运行，例如每周分类、夜间依赖检查或每月清理。 | [定时代理](/agent-platform/cloud-agents/triggers/scheduled-agents/)或[定时代理快速入门](/agent-platform/cloud-agents/triggers/scheduled-agents-quickstart/) | Oz Web 应用 Runs 页面、Warp 应用中的代理管理面板、定时历史记录和云端代理会话链接 |
| Slack | 队友应通过 Slack 消息或线程委托工作。 | [Slack 集成](/agent-platform/cloud-agents/integrations/slack/) | Slack 线程更新、Oz Web 应用 Runs 页面、Warp 应用中的代理管理面板和共享运行会话 |
| Linear | 问题、评论或分配应启动代理。 | [Linear 集成](/agent-platform/cloud-agents/integrations/linear/) | Linear 问题更新、Oz Web 应用 Runs 页面、Warp 应用中的代理管理面板和共享运行会话 |
| GitHub Actions | 仓库事件、PR 工作流、问题工作流或 CI 失败应启动代理。 | [GitHub Actions](/agent-platform/cloud-agents/integrations/github-actions/) | GitHub Actions 日志、PR 或问题评论、Oz Web 应用和云端代理运行 |
| Oz CLI | 你想从终端、脚本或本地自动化启动命名云端运行。 | [Oz CLI](/reference/cli/#running-agents-remotely-oz-agent-run-cloud) | CLI 输出、Oz Web 应用 Runs 页面、Warp 应用中的代理管理面板和云端代理会话链接 |
| Oz API 或 SDK | 你的内部系统应以编程方式创建、查询或监控运行。 | [Oz API 和 SDK](/reference/api-and-sdk/) | 你的系统、API 结果、Oz Web 应用和运行会话 |

## 选择工作流模式

### 运行重复性维护

使用[定时代理](/agent-platform/cloud-agents/triggers/scheduled-agents/)处理应按固定节奏执行的任务。适合的场景包括：

* 依赖更新检查
* 过期问题或 PR 分类
* 仓库卫生清理
* 文档刷新
* 定期报告或审计

每个定时运行都会启动一个新的云端代理会话，并记录自己的任务历史，因此你可以查看运行了什么、何时运行以及代理做了什么。

### 从 Slack 或 Linear 委托工作

当任务源自团队对话或问题上下文时，使用 [Slack](/agent-platform/cloud-agents/integrations/slack/) 或 [Linear](/agent-platform/cloud-agents/integrations/linear/)。这些集成最适合：

* 将 Slack 线程转化为实现任务
* 要求代理调查 Linear 问题
* 从错误报告或产品请求生成 PR
* 让队友在不打开 Warp 的情况下监控进度

代理会将进度更新发布回源线程或问题，并提供共享运行链接用于深入检查。

### 响应 GitHub 事件

当触发器应与仓库事件关联时，使用 [GitHub Actions](/agent-platform/cloud-agents/integrations/github-actions/)。

例如：

* 在 PR 打开时进行审查
* 响应 `@oz-agent` 评论
* 按计划总结问题
* 在 CI 失败时尝试修复
* 为审查评论建议修复

GitHub Action 可以将事件数据、先前步骤输出和仓库上下文传递到代理提示词中。根据你授予的工作流权限，代理可以评论、审查或打开分支。

### 从脚本或内部系统启动运行

对于脚本和终端工作流，使用 [Oz CLI](/reference/cli/#running-agents-remotely-oz-agent-run-cloud)。当其他服务应创建或监控运行时，使用 [Oz API 和 SDK](/reference/api-and-sdk/)。这适用于：

* 内部仪表板
* 自定义 Webhook
* GitHub Actions 之外的 CI 系统
* 由你自己的调度器管理的定期任务
* 需要以编程方式查询运行状态或结果的工作流

使用 `--name` 一致地命名云端运行，以便你的团队以后可以筛选和审查相关运行。

## 在部署前定义运行

在部署无人值守代理之前，定义：

* **触发器**——什么启动运行：定时、Slack、Linear、GitHub 事件、CLI 命令、API 请求或其他自动化。
* **上下文**——代理需要哪些仓库、问题、线程、PR、日志或文件。
* **环境**——代理运行的位置，包括仓库、镜像、设置命令、密钥和任何 MCP 服务器。
* **权限**——代理在 GitHub、Slack、Linear 或其他系统中可以读取或写入什么。
* **输出**——代理应评论、打开 PR、生成工件、发布摘要还是仅报告发现。
* **审查路径**——人类将在哪里检查运行、验证结果和批准更改。

如果代理可以更改代码或基础设施，请保持指令范围狭窄并明确指定验证要求。

## 审查无人值守运行

无人值守并不意味着不可见。使用以下界面审查发生了什么：

* [Oz Web 应用](/agent-platform/cloud-agents/oz-web-app/)——从浏览器或移动设备查看运行、定时任务、运行元数据和会话记录。
* [管理云端代理](/agent-platform/cloud-agents/managing-cloud-agents/)——按来源、状态、日期、创建者或触发器筛选运行。
* [云端代理会话共享](/agent-platform/cloud-agents/viewing-cloud-agent-runs/)——检查提示词、计划、命令、日志、输出以及可用的后续消息。
* [Oz API 和 SDK](/reference/api-and-sdk/)——查询运行并围绕状态、运行时间或结果构建内部监控。

当运行创建了 PR 时，在 PR 描述或评论中包含云端运行链接。有关模板，请参阅[将代理会话上下文附加到 GitHub PR](/guides/agent-workflows/how-to-attach-agent-session-context-to-github-prs/)。

## 从一个可审查的工作流开始

在部署多个无人值守代理之前，先从一个狭窄的工作流开始：

1. 选择一个触发器和一个仓库。
2. 使用集中的提示词或技能。
3. 手动运行或使用 **Run now** 运行，然后再启用定期计划。
4. 确认运行拥有正确的环境、密钥和权限。
5. 检查输出和会话记录。
6. 在合并代码更改之前添加审查或批准步骤。
7. 仅在首次运行可预测后扩展工作流。
