### 1. 为什么图像很重要

人类处理视觉信息比文本快得多——AI 也是如此。\
\
当你试图解释一个 UI 问题时（"这个按钮偏了几个像素"），用语言描述可能很笨拙。\
\
这就是 Warp 支持图像作为上下文的原因——让你直接将截图附加到提示词中。

> 🧠 "一图胜千言"——尤其是在调试 UI 或构建前端组件时。

---

### 2. 图像上下文的作用

图像上下文允许你：

* 将一个或多个截图附加到代理查询
* 为错误、设计或功能提供视觉参考
* 让代理直观地理解你的意思

这在前端任务中特别有用，比如：

* 从 Figma 重建设计
* 识别布局错位
* 调试视觉错误

---

### 3. 从 Figma 构建 MCP 市场

获取 MCP 服务器市场（MCP Server Marketplace）的 Figma 设计稿并将其用作 Warp 的输入。

#### 第 1 步：捕获设计稿

截取你的设计截图（例如，MCP 市场布局）。

#### 第 2 步：附加图像

在 Warp 中：

1. 点击输入栏中的 📎 图像图标
2. 选择你的截图
3. 确认它已附加到查询

---

### 4. 运行任务

一旦附加，Warp 的代理：

1. 检测附加的图像
2. 搜索你的仓库（例如 `collection.rs`）
3. 生成从设计稿重建 UI 的差异
4. 创建相应的组件和布局逻辑

你可以在代码差异查看器中查看和编辑这些差异，类似于 GitHub 的差异界面。

> 💡 Warp 建议使用较小、集中的差异——代理在迭代工作时表现更好。

---

### 5. 查看结果

代理构建了：

* MCP 市场的 UI 组件
* 三个 MCP 服务器（`Linear`、`GitHub`、`Stripe`）的静态数据
* 正确的渲染逻辑和样式

在 Warp 中验证 UI：

> "它与设计稿几乎完美匹配——本来需要我两天的东西在 20 分钟内完成了。"

---

### 6. 优化性能

因为图像会消耗大量令牌，Warp 会自动：

* 在客户端调整图像大小
* 在发送前智能压缩
* 在不损失清晰度的情况下最小化令牌使用
