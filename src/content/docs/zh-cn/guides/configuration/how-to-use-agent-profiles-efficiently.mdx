代理配置文件控制你的编码代理在不同上下文中的行为。\
它们定义代理可以读取、规划或执行的内容——以及它拥有多少自主权。

为了展示配置文件如何改变工作流，我们将使用两个配置文件构建一个 NFL 预测器应用：

* 战略型代理
* YOLO 代理

### 战略型代理

基础模型：GPT-5\
规划模型：Claude 4 Opus

配置：

* 应用代码差异 → _代理决定_
* 读取文件 → _始终允许_
* 创建计划 → _始终允许_
* 执行命令 → _先询问_

运行时：

1. 代理提出澄清性问题（例如，_你想抓取球员数据和赛程吗？_）
2. 构建详细的 14 步计划
3. 请求用户输入环境变量

它彻底且安全——但如果缺少设置细节，它经常暂停。

---

### YOLO 代理

配置：

* 应用代码差异 → _始终允许_
* 读取文件 → _始终允许_
* 创建计划 → _从不_
* 执行命令 → _始终允许_

此代理跳过冗长的规划。\
它快速构建项目，跳过可选的验证，专注于核心功能：

* 数据导入
* 球员统计数据
* 得分计算

它避免不稳定的端点，并快速生成可用的数据集——尽管检查较少。

---

### 比较两者

| 特性 | 战略型代理 | YOLO 代理 |
| --------- | ------------------- | ------------------ |
| 规划 | 详细（14 步） | 最少（10 步） |
| 安全性 | 高 | 低 |
| 速度 | 中等 | 非常快 |
| 适用场景 | 生产项目 | 快速原型 |
